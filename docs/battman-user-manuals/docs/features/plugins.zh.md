# 原生插件

Battman 可以接收来自“文件”或其他应用的 `.battman` 软件包文稿。导入时会先验证并隔离软件包，**不会**运行插件。你可以在**更多 → 插件**中查看它。

## 信任与启用

官方插件只有在发布者及其准确扩展范围获得 Battman 的离线签名信任元数据授权后才会被接受。有效的第三方软件包默认仍不受信任。Battman 会显示插件标识符、验证状态、请求的扩展点，以及软件包签名中可选的作者名称、主页和支持邮箱。发布者指纹和软件包摘要位于**技术详情**中，并会缩短显示；轻点即可复制完整内容以便独立核对。作者和联系信息只是软件包发布者的声明，不能建立信任。随后 Battman 才会显示原生代码警告并提供两种选择：

- 只批准当前准确构建；或
- 批准此发布者今后为同一插件及同一扩展范围发布的版本。

这两种选择都不能让原生代码变得安全。插件一旦载入，就能读取或更改 Battman 可以访问的任何内容、绘制任意界面、使用私有 API 或网络、使应用崩溃并破坏数据。不要批准你不信任其作者或准确字节内容的软件包。签名、摘要、架构、ABI、依赖、撤销、回滚或平台载入检查失败都不能被绕过。

第三方载入还有一个默认关闭的总开关。安装及启用/停用更改会在重新启动 Battman 后生效。越狱安装可以从 Battman 私有应用数据目录或系统插件目录载入经过验证的软件包。仅使用 TrollStore 时，需要将插件嵌入替换版 Battman TIPA 并重新签名整个应用；仅把原生 bundle 导入数据目录并不属于已支持行为。

## 恢复与移除

如果 Battman 在尝试载入第三方插件后未能完成启动，下次启动会进入不载入第三方插件的安全模式，并标出最后尝试的构建。你也可以为下次启动选择**不载入第三方插件启动**，随后在插件页面停用或移除准确的软件包。Battman 可以移除自己私有导入的副本；随应用附带或由 APT/dpkg 管理的文件必须通过相应安装渠道更新或移除。

软件包和信任验证可以完全离线完成。比较摘要、验证签名、查询本机批准/回滚状态和进入安全模式都不需要网络。

## 诊断与支持

**导出诊断** 会先显示隐私说明，再打开系统分享面板。纯文本报告包含 Battman
版本/构建号、生成时间、插件标识符与软件包摘要、来源、信任和启用状态，以及有界的错误域/错误码。报告不包含插件文件、私钥、电池测量值、设备标识符、本地化错误文本或文件系统路径。已安装插件列表仍可能属于敏感信息，因此请在分享前检查文本和接收者。

普通且不敏感的缺陷可使用公开 issue tracker。安全报告和私密诊断应遵循仓库的
`SECURITY.md` 政策。
