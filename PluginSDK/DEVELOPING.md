# Developing a Battman Analytics plug-in

This guide ships inside the SDK source archive. It needs no Battman checkout.
The public API is the three headers in `include/`; the package schemas are in
`schema/`. The SDK major, native ABI, package format, and Analytics card
interface are all version 1. Battman 1.1.0 does not change those numbers.

The SDK Analytics card and Charge Gauge are developer source examples. The
formal 1.1.0 release ships no compiled example plug-ins, example `.battman.zip`
files or Debian add-ons, and embeds neither example in its TIPA. The commands
below build local development/test artifacts; they do not add examples to the
release.

## Toolchain and dependencies

Use macOS with Xcode and an installed iPhoneOS SDK, `make`, and Python 3.10 or
newer. The native build links Foundation, UIKit, QuartzCore, and CoreGraphics;
it needs no third-party native library, package manager, or host source. The
Makefiles target `arm64-apple-ios12.0` and apply local ad-hoc code signatures.
They do not provision an Apple account. An iPhoneSimulator build is not a
device payload.

Choose an absolute SDK path. In the SDK archive root, run:

```sh
SDK_ROOT="$PWD"
export PYTHONDONTWRITEBYTECODE=1
xcode-select -p
xcrun --sdk iphoneos --show-sdk-path
python3 "$SDK_ROOT/Tools/generate-sdk-contract.py" --check
```

When using a full Battman checkout instead, set `SDK_ROOT="$PWD/PluginSDK"`.
If Xcode is not the selected toolchain, set `DEVELOPER_DIR` to its existing
`Contents/Developer` directory before these commands and pass it to `make`.

Only publisher-key inspection, signing, and signature verification need the
Python `cryptography` library. The SDK includes a copy of the release tooling's
hash-pinned `requirements.txt` for CPython 3.13 on macOS arm64/x86_64 and Linux
x86_64. Install that environment once, outside the source tree:

```sh
python3.13 -m venv /tmp/battman-sdk-tools
. /tmp/battman-sdk-tools/bin/activate
python -m pip install --only-binary=:all: --require-hashes \
  -r "$SDK_ROOT/requirements.txt"
```

This setup downloads dependencies; subsequent package operations are offline.
For an offline setup, provide reviewed matching wheels and add
`--no-index --find-links /path/to/wheelhouse` to the install command. Do not
remove hash checking when a platform has no matching pinned wheel. Python
package binaries and the Apple SDK are not bundled or relicensed by this source
archive. Retain their own notices if distributing a separate tool environment.

The signer requires `cryptography`'s deterministic ECDSA support. An older
installation may import successfully but still lack that operation; use the
pinned environment for signing. Signing keys are existing publisher inputs,
never generated by the examples or included in the SDK.

## Create and build

The output directory must not exist; its parent must exist. These commands
create an independent project and keep compiled products outside SDK sources:

```sh
python3 "$SDK_ROOT/Tools/create-analytics-card.py" \
  --plugin-id com.example.battman.charge \
  --card-id com.example.battman.charge.primary \
  --display-name "Charge Card" \
  --author-name "Example Developer" \
  --homepage-url "https://example.com/battman-card" \
  --support-email "support@example.com" \
  --output /tmp/ChargeCard
make -C /tmp/ChargeCard SDK_ROOT="$SDK_ROOT" \
  BUILD_DIR=/tmp/ChargeCard-build -j1 all
```

The result is `/tmp/ChargeCard-build/BTAnalyticsExample.bundle`. Names beginning
with `BTAnalyticsExample` are implementation names, not the plug-in identity.
The generator changes the identifiers and display strings; give Objective-C
classes your own unique prefix before shipping multiple implementations.
The generated `LICENSE` preserves the copied example's MIT notice.

For the unmodified example, use:

```sh
make -C "$SDK_ROOT" BUILD_DIR=/tmp/BattmanSDKExample -j1 example
```

This also creates `BTAnalyticsExample.embedded.o` for host integration tests.
External authors ship the bundle. Merely linking an embedded object is not a
way to install a plug-in into an existing Battman app.

`all`/`example` runs `Tools/validate-native-bundle.sh`. It checks bundle identity,
the sole exported entry symbol, system dependency paths, and the platform code
signature. The native host additionally checks architecture, Mach-O load
commands, allowed dependencies, deployment version, ABI, and actual loadability.

## Implement the public contract

Use `Examples/AnalyticsCard/BTAnalyticsExamplePlugin.m` as the complete minimal
reference: registration, view creation, four grid sizes, immutable snapshots,
accessibility, lifecycle callbacks, and schema-v1 restoration. The card owns
its root `UIView`, subviews, layers, drawing, gestures, resources, and content
accessibility. Battman owns the cell, grid, editing controls, scheduling, and
restoration envelope. UIKit callbacks arrive on the main thread. Stop optional
animation/work when display ends, and discard caches on memory warnings.

Export exactly `BattmanPluginEntryPointV1`. Return a descriptor whose storage
and C strings remain valid, and initialize each public structure with its
compiled `sizeof` and `BT_PLUGIN_ABI_VERSION_1`. Before registration, validate
`host`, its ABI, `BT_PLUGIN_HOST_V1_MINIMUM_SIZE`, and `registerExtension`.
Check an optional tail's size before reading its pointer; do not require the
current whole-table size from older hosts. The current LP64 host table is 40
bytes, with a frozen 24-byte required prefix. `log` and `preferredLanguage` are
optional. [COMPATIBILITY.md](COMPATIBILITY.md) defines the evolution rules.

The descriptor's plug-in ID and `pluginVersion` must match the manifest's
`pluginIdentifier` and **buildVersion**. Keep `BUILD_VERSION`, `Info.plist`
`CFBundleVersion`, and the manifest build version synchronized. Display version
is a separate user-facing value. Keep bundle identifiers, payload paths, and
extension declarations consistent; the builder derives `files` and
`payload.codeIdentity`, which must be absent from your input template.

Register `com.torrekie.battman.analytics.card.v1`, interface version `1`, with an
object conforming to `BAAnalyticsCard`. Every extension ID must be unique and
namespaced under your plug-in ID. Registration is transactional: a failure
rejects all registrations from that plug-in. Native images stay mapped until
process exit; update, disable, and revocation changes require a restart.

Use only the public headers and documented Apple APIs. Do not resolve symbols
from the Battman executable, instantiate its implementation classes, call
private controllers, or depend on extra keys observed in a snapshot dictionary.
An agent implementing a card should preserve the public contract and use
`SDKContractV1.json` as a check, never regenerate it to hide a mismatch.

## Read metrics

Implement `analyticsCardContentView:didReceiveMetricSnapshot:`. Use
`valueForMetricIdentifier:` and `historyForMetricIdentifier:` with the macros
in `BAAnalyticsMetricSnapshot.h`. Values are immutable `NSNumber` objects;
missing values are `nil`, missing histories are empty arrays. A missing value
is not zero. Validate finite numbers before drawing, and handle unknown keys
or future charging states without crashing. Do not poll hardware or create a
second sensor timer. Snapshot timestamps describe sample time; do not assume
fixed delivery intervals or unlimited history.

All public v1 metric macros are listed below. Each name has the
`BAAnalyticsMetric` prefix, for example `BAAnalyticsMetricStateOfChargePercent`.

| Macro suffix | Unit / value |
| --- | --- |
| `StateOfChargePercent` | percent, 0–100 |
| `BatteryHealthPercent` | percent; do not assume a maximum of 100 |
| `AverageTemperatureCelsius` | degrees Celsius |
| `AverageCurrentMilliamps` | signed mA; preserve the supplied sign |
| `VoltageMillivolts` | mV |
| `AveragePowerWatts` | W; a distinct measurement from calculated current × voltage |
| `CycleCount` | current cycle count |
| `DesignCycleCount` | design cycle count |
| `BatteryUptimeSeconds` | seconds |
| `RemainingCapacityMilliampHours` | remaining capacity, mAh |
| `FullChargeCapacityMilliampHours` | full-charge capacity, mAh |
| `DesignCapacityMilliampHours` | design capacity, mAh |
| `ChargingState` | `BAAnalyticsChargingState`: unavailable −1, not charging 0, charging 1, paused 2 |
| `ChargingLimitPercent` | percent |
| `ChargingLimitServiceActive` | Boolean |
| `ChargingLimitReached` | Boolean |

Availability depends on the device, OS, data source, and enabled host features.
The public snapshot does not grant access to the host's persistent statistics
or private sensor interfaces. A card should show unavailable state or explain
its narrower data requirements when these metrics do not support its purpose.

## Follow the host language

Battman's interface language can differ from the system language. During
`registerPlugin`, read `host->preferredLanguage` only after the size check:

```objc
NSString *language = nil;
if (host->structSize >=
    BT_PLUGIN_STRUCT_SIZE_THROUGH(BTPluginHostV1, preferredLanguage) &&
    host->preferredLanguage) {
    language = [NSString stringWithUTF8String:host->preferredLanguage];
}
```

This snippet assumes the required host prefix was already validated. The UTF-8
BCP-47 string is borrowed for registration only; keep an owned Objective-C
string if needed later. If absent, use the system preference. Use an anchor
class in your bundle with `+[NSBundle bundleForClass:]`, select a matching
localization with `preferredLocalizationsFromArray:forPreferences:`, and load
strings from that `.lproj`. Do not look up plug-in strings in the app's main
bundle or change process-global language defaults.

Include resources in the bundle **before** code signing. The minimal generated
project has no resource-copy rule; add one to its Makefile if adding `.lproj`
files. The full repository's `OfficialPlugins/ChargeGauge` demonstrates this
rule and includes English, German, Simplified Chinese, and Traditional Chinese
resource strings, localized accessibility, optional host-language selection, and iOS 12
appearance fallbacks. Its source is distributed separately under Battman's
repository license; it is not included in this MIT SDK subtree. SDK v1 has no
live language-change callback, so do not assume one will arrive.

## Build, publisher-sign, and verify the package

Platform code signing and publisher signing are separate. First finish and
platform-sign the bundle; then package its exact bytes; finally sign the exact
`Manifest.json` bytes with an existing ECDSA P-256 publisher key. The tools
refuse existing output files, so choose a fresh work directory:

```sh
PACKAGE_WORK=$(mktemp -d /tmp/battman-card-package.XXXXXX)
PUBLISHER_KEY_ID=$(python3 "$SDK_ROOT/Tools/publisher-key-id.py" \
  /path/to/publisher-public.pem --raw-output "$PACKAGE_WORK/publisher-public.p256")
python3 "$SDK_ROOT/Tools/render-example-manifest.py" \
  --template /tmp/ChargeCard/ManifestTemplate.json.in \
  --publisher-key-id "$PUBLISHER_KEY_ID" \
  --output "$PACKAGE_WORK/ManifestTemplate.json"
python3 "$SDK_ROOT/Tools/Package/build-plugin-package.py" \
  --manifest-template "$PACKAGE_WORK/ManifestTemplate.json" \
  --payload /tmp/ChargeCard-build/BTAnalyticsExample.bundle \
  --publisher-public-key "$PACKAGE_WORK/publisher-public.p256" \
  --output "$PACKAGE_WORK/com.example.battman.charge.battman"
```

Replace `/path/to/publisher-public.pem` with the existing public-key file. The
package builder takes the **65-byte uncompressed `.p256` point**, not PEM. The
key-ID tool prints the lowercase SHA-256 fingerprint of that point. Review
that fingerprint through your established publisher identity process.

Transfer the unsigned package to the controlled signer. Only there, using the
actual package and existing encrypted key paths, run:

```sh
python3 "$SDK_ROOT/Tools/Package/sign-plugin-package.py" \
  /path/to/com.example.battman.charge.battman \
  --private-key /secure/publisher-private.pem \
  --password-file /secure/publisher-password
python3 "$SDK_ROOT/Tools/Package/verify-plugin-package.py" \
  /path/to/com.example.battman.charge.battman
```

Keep private keys and passwords outside source, build, and delivery folders.
No production key, official delegation, or release approval is created by this
workflow. Never edit a signed manifest or re-sign a packaged bundle in place;
rebuild the package and publisher signature from the final payload instead.
Increase `releaseSequence` monotonically for a new release under the publisher
key. Reusing one sequence for different package bytes is equivocation; lowering
it is rollback.

Portable verification checks the envelope, inventory, hashes, and publisher
signatures without executing the payload. Its report intentionally says
`nativeVerificationRequired: true`. It does not establish official trust or
prove that iOS can load the bundle. Signature validity is not a code audit.

## Install and check the card

A `.battman` file is a directory package. A `.battman.zip` download is its
transport wrapper: extract it to the `.battman` root before document import.
Battman imports into quarantine and verifies it before activation. Unknown
third-party publishers require the user's explicit approval and the global
third-party plug-in switch. Structural, signature, architecture, dependency,
rollback, and ABI failures cannot be approved away.

On TrollStore, imported native code can remain at **Requires Battman Reinstall**
until incorporated into a correctly signed replacement app and explicitly
installed. An SDK build or valid publisher signature alone does not bypass that
platform restriction. Enable/update/disable changes take effect on a later app
launch.

Before distributing, exercise all advertised sizes, missing metrics, editing,
restoration, accessibility, appearance, and visibility changes in an authorized
host environment. Validate the bundle and publisher package again after the
final build. State what was actually checked, the supported OS/device range,
and any limitations; compiling with an iOS 12 deployment target is not evidence
of a complete physical-device matrix.
